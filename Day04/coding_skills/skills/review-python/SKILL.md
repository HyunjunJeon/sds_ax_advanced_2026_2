# 코드와 재현 근거로 리뷰하기

1. 요청한 리뷰 범위와 프로젝트 README를 읽고 관련 코드·테스트를 확인한다.
2. 수정 없는 리뷰에서는 소스·테스트·README를 바꾸지 않는다. 필요한 검사는 실행할 수 있다.
3. 의심한 문제를 반례나 기존 테스트로 확인한다. 확인한 결함과 아직 검증하지 못한 우려를 구별한다.
4. 지적마다 파일·줄, 문제가 발생하는 입력, 실제 영향, 수정 방향을 적는다.
   실행하지 않은 테스트를 통과했다고 말하거나 스타일 취향을 결함으로 꾸미지 않는다.
5. [리뷰 양식](assets/review-template.md)을 읽고 `/artifacts/review.md`에 리뷰를 작성한다.
   발견한 결함이 없으면 없다고 적고 검토 범위와 한계를 남긴다.
6. `show_diff`로 프로젝트에 의도하지 않은 변경이 없는지 확인하고 최종 답변에 보고서 경로를 남긴다.
