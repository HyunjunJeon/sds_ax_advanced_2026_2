## 실제 서비스 연결의 확인 범위

업무 정상 초기 상태로 두 턴의 개발 연결 점검을 세 번 실행했다. 수강생용 승인 Dataset 실험이나
baseline/candidate 성능 비교가 아니다. 모든 결과를 `outputs/`와 각 파일의 `_runs/`에 보존했다.

| 기록 | 모델 호출 | 결과 |
|---|---:|---|
| `course_connection_check.json` | 3 | `BadRequestResponseError`, 실행 오류 |
| `course_connection_diagnostic.json` | 6 | HTTP 400, 부분 상태와 오류 보존 |
| `course_connection_provider_diagnostic.json` | 10 | 질문 → 주문 번호 제공 → 취소·환불·재고 복원 완료 |

성공한 한 건만으로 연결 안정성을 입증하지 않는다. 앞선 400 오류의 공급자 상세 원인은 미확정이다.
모델을 교체하거나 예산을 올려 이 결과를 숨기지 않았다. 실패한 행도 성능 비교에서 제외해서는 안 된다.

Langfuse 인증 확인은 성공했다. 새 Dataset·Run·Trace·Score의 실제 외부 쓰기는 실행하지 않았으며,
그 연결은 가짜 SDK 클라이언트로 검증했다. 새 수업의 실제 Judge 채점·사람 보정·후보 실험 전체는
아직 실행하지 않았다. 이 작업에서는 검수·가설·사람 판정을 대신 작성하지 않았다.
