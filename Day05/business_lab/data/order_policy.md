# 주문 취소 업무 계약 — 교육용 가상 정책

정책 버전: `order-policy-v1` · 기준일(as_of): 2026-09-10.
이 정책은 강의자가 검수한 예시 계약이며 실제 쇼핑몰 규정이나 법률 안내가 아니다.
모든 금액은 예제 결제 API의 USD 정수 센트다. 환불 완료는 결제 원장에 등록됐다는 뜻이며,
카드사 정산 완료까지 의미하지 않는다.

## P1. 고객과 대상

인증 고객은 서버 환경에서 결정한다. 모델이 고객 ID를 바꿔 권한을 얻을 수 없다.
본인 주문만 조회·처리한다. 주문 번호가 없거나 존재하지 않으면 확인 질문을 한다.
다른 고객의 주문은 거절하고, 주문·결제·재고를 변경하지 않는다.

## P2. 취소 가능 상태와 동시 변경

`paid` 주문만 취소를 시작할 수 있다. `cancelling` 주문은 부분 완료 상태를 조회해 이어서 처리한다.
`shipped` 주문은 거절한다. `cancelled` 주문은 상태만 확인하며 환불·재고 복원을 다시 시도하지 않는다.
취소 시작에는 마지막으로 조회한 version을 보내며, 충돌 시 재조회·정책 재확인 후 판단한다.
다른 작업자가 출고한 변경은 되돌리지 않는다.

## P3. 부분 완료와 완료 조건

취소 시작 → 잔여 결제액 환불 → 예약 재고 복원 → 주문 취소 완료 순서로 처리한다.
각 서비스 호출은 따로 커밋된다. 중간 실패를 전체 롤백한 것처럼 해석하지 않는다.
완료 조건은 주문 `cancelled`, 전액 환불 기록, 주문 수량만큼 재고가 정확히 한 번 복원된 상태다.
다른 주문, 다른 고객의 결제, 주문 금액·통화·수량, 다른 상품 재고는 보호 상태다.

## P4. TIMEOUT과 멱등성

환불 TIMEOUT은 결과 미확정이다. 결제 원장을 조회해 처리 여부를 확인한 뒤 다음 행동을 정한다.
미처리가 확인되면 같은 요청의 같은 멱등 키로 재시도한다. 환불 시도 한도는 2회다.
이미 환불이 처리됐다면 추가 환불을 요청하지 않고 나머지 단계를 수행한다.
한도 내 해결하지 못하면 현재 부분 완료 상태를 보존하고 업무 티켓으로 담당자에게 넘긴다.
재고 복원도 주문 단위로 멱등적이어야 한다.

## P5. 최종 안내

완료는 최종 주문 조회로 확인한 뒤 안내한다. 부분 완료·미확정·거절을 완료라고 말하지 않는다.
미완료라면 현재 상황과 담당자의 후속 확인을 안내한다. 원장에 기록된 환불 금액만 말한다.
응답의 구조화 필드와 자유 문장은 각각 코드 검사와 Judge/사람 검토로 확인한다.

## 실습의 경계

하나의 SQLite 연결 안에서 서비스별 커밋을 재현한다. 실서비스 간 네트워크·동시 실행을
완전히 재현하지 않는다. 출고 경합과 환불 응답 손실은 fixture의 장애 주입으로 재현한다.
원장은 초기 상태마다 격리되며 실제 결제·배송·알림 서비스에는 연결하지 않는다.
